Implemented the production WebDocument vertical slice.

Production path:
- `CanvasApp` probes `webCanvas.get`; migrated Main documents open in `WebCanvasEditor`, legacy documents stay in `CanvasEditor`.
- Existing legacy editor exposes an explicit, confirmed `Web document` migration action on Main only.
- Migration saves the prior CanvasDocument to design version history, converts it to WebDocument, then atomically replaces Main with storage version 3.
- `webCanvas.applyTransaction` validates and applies WebTransactions server-side, uses revision compare-and-swap, logs transactions, emits realtime invalidations, and returns the persisted WebDocument.
- Reload detects the WebDocument and reopens the web editor.

Editor slice:
- Native DOM under pan/zoom camera.
- DOM ID selection/hover and separate measured overlays.
- Browser `getBoundingClientRect` and `getComputedStyle` drive editor geometry.
- Move and resize commit CSS through WebTransactions.
- Double-click text editing commits WebText changes.
- DOM tree, element creation for the requested tags, delete, undo/redo, save state.
- Inspector edits tags, attributes, and requested layout/typography/appearance CSS declarations directly.

Migration proof:
- Frame, Text, Shape, and Image mappings covered; legacy CSS conversion reuses the existing boundary compiler only during migration.
- Components/instances remain explicit migration warnings.

- `bun run test`: 69 files, 515 tests passed.
- `bunx tsc --noEmit`: passed.
- `git diff --check`: passed.
- RPC integration test proves legacy migration, backup version creation, web transaction persistence, and reload.
- Editor test proves production chrome, native DOM rendering, selection, and CSS inspection.
